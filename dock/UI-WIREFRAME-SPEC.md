# ПЛАНЕТКИ — UI-WIREFRAME-SPEC.md

## 0. Назначение

Этот документ описывает структуру основного игрового интерфейса **этапа 1 — Племя**.

Цель — сделать интерфейс:
- понятным без обучения;
- визуально живым;
- не похожим на debug-режим;
- удобным для мыши;
- хорошо читаемым на 1920×1080;
- расширяемым для этапов 2–5.

Главный принцип:

> Карта показывает мир.  
> UI показывает управление.  
> Служебные данные появляются только по запросу.

# 2. ВИЗУАЛЬНЫЙ СТИЛЬ UI

## 2.1. Общий стиль

Этап 1 должен выглядеть как смесь:

- старой карты;
- пергамента;
- ручных чернильных линий;
- деревянных / бронзовых рамок;
- тёмных металлических элементов для интерактивных кнопок;
- нарисованных вручную иконок.

Избегать:
- sci-fi HUD;
- стеклянных панелей;
- кислотных цветов;
- слишком современных flat-design элементов.

# 3. TOP HUD

## 3.1. Расположение

Полная ширина экрана.

Высота:
`70–90 px`

Не должен перекрывать карту сильнее необходимого.

## 3.2. Левый блок

Показывает время:

```text
День 3 · Месяц 6 (Лето) · Год 1
Эпоха I — Племя
```

При наведении на дату:
- сезон;
- число дней до следующего сезона;
- продолжительность года;
- текущие сезонные эффекты.

## 3.3. Центральный блок ресурсов

Порядок:

```text
🍖 Еда
🪵 Дерево
🪨 Камень
⛏ Металл
🪙 Кубрики
📘 Знания
```

Каждый ресурс:

```text
Еда
569
+14/д
```

или компактно:

```text
🍖 569  +14/д
```

Положительный прирост:
зелёный/нейтральный.

Отрицательный:
красный.

Нулевой:
серый.

Справа:

```text

1x
```

- золотая рамка;
- иконка и текст остаются читаемыми;
- активное состояние должно быть очевидным.

# 14. РЕЖИМ РАЗМЕЩЕНИЯ ЗДАНИЯ

После нажатия «Строить»:

1. закрываются лишние UI-панели;
2. появляется строительная сетка;
3. sprite здания следует за курсором;
4. допустимая область подсвечивается;
5. недопустимая область — красным;
6. tooltip объясняет причину.

Пример:

```text
Нельзя построить здесь:
слишком близко к воде.
```

ESC:
отмена.

ЛКМ:
подтверждение.

ПКМ:
отмена.

# 23. ПРИОРИТЕТЫ СОБЫТИЙ

## INFO
Не останавливает игру.

Пример:
- родилось 2 ребёнка;
- хорошая охота.

## WARNING
Показывает заметное уведомление.

Пример:
- нехватка жилья;
- ранен охотник.

## IMPORTANT
Открывает окно.

Пример:
- дипломатическое предложение;
- закон;
- религиозный конфликт.

## CRITICAL
Ставит игру на паузу.

Пример:
- нападение;
- бунт;
- смерть правителя;
- катастрофа.

# 27. ЛЮДИ НА КАРТЕ

Не симулировать всех визуально.

Для поселения с 89 жителями достаточно:
`10–25 visual agents`.

Типы:
- idle;
- walking;
- carrying;
- working;
- gathering;
- builder;
- hunter;
- child.

Количество визуальных фигур зависит от zoom.

---

# 28. VISUAL AGENT — НЕ GAME ENTITY

Важно:

декоративный человек ≠ реальный отдельный житель.

Настоящая демография остаётся статистической.

Visual Agent:
- получает случайную роль;
- выбирает визуальную точку;
- проигрывает короткую анимацию;
- возвращается;
- может быть уничтожен и создан заново без изменения population simulation.

---

# 29. ЛАНДШАФТ

Обычный режим должен скрывать grid.

Визуальные переходы:
- трава ↔ земля;
- трава ↔ песок;
- песок ↔ мелководье;
- мелководье ↔ море;
- поле ↔ трава;
- лес ↔ луг.

Нужны edge/corner tiles.

---

# 30. ВОДА

Минимум 3 визуальных уровня:

```text
DeepWater
Water
ShallowWater
```

Берег:
отдельный transition layer.

Если возможно:
легчайшая анимация бликов/волн.

---

# 31. ЛЕС

Не показывать лес как одиночные одинаковые ёлки.

Нужны:
- dense forest;
- sparse forest;
- forest edge;
- forest corner;
- clearing;
- mixed tree clusters.

---

# 32. INPUT PRIORITY

Критическое правило:

```text
UI input > map input
```

Если курсор над `Control`:
- scroll не идёт камере;
- drag не идёт камере;
- click не проходит на карту.

Если открыт modal:
- map input блокируется полностью.

---

# 33. MOUSE WHEEL

```text
     v

  /        \

 |          |
```

Это должно быть централизованно.

- крупные природные элементы;

- важные названия поселений;
- active notifications.

Не постоянно:
- grid;
- ресурсы;
- fertility;
- detailed stats;
- progress каждого здания;
- все tooltips.

# 50. КРИТЕРИИ ПРИЁМКИ

Работа считается принятой, если новый игрок без дополнительных объяснений способен за 1–2 минуты понять:

- где его поселение;
- сколько у него жителей;
- сколько еды;
- растёт запас еды или падает;
- что уже построено;
- что строится сейчас;
- как построить новое здание;
- где соседнее племя;
- где события;
- как открыть законы;
- как открыть религию;
- как открыть армию;
- как поставить игру на паузу;
- как изменить скорость.

Дополнительный UX-критерий:

> если открыто окно UI и пользователь крутит колесо над ним, камера не должна масштабироваться.

# 51. ФИНАЛЬНЫЙ UX-ПРИНЦИП

Интерфейс должен создавать ощущение:

> «Я наблюдаю за своим народом и управляю его развитием».

а не:

> «Я управляю таблицей тайлов и числовых маркеров».

Игрок должен помнить:
- где стоит его первый дом;
- где находится святилище;
- где живут соседи;
- где произошло важное событие;
- как поселение выросло.

Это главный критерий дизайна UI первого этапа «Планеток».
