# РЕЕСТР LEGACY-НАЧИСЛЕНИЙ И СТАТУС ПЕРЕХОДА НА ФИЗИЧЕСКУЮ СИМУЛЯЦИЮ (PLANETKI)

Настоящий документ фиксирует аудит всех экономических начислений в кодовой базе проекта `PlanetKI`, классифицирует их источники, статус вывода из абстрактно-пассивной модели в реальную агентно-физическую симуляцию (в соответствии с правилом `AGENTS.md` — запрет заглушек и декоративного кода).

## 2. Подсистема партий пищи (`food_batches`) и порчи

* Пища больше не является безликим абстрактным числом в экономике.
* Каждая доставка пищи собирателем или охотником регистрирует запись в `food_batches`:
  - `batch_id`: уникальный идентификатор партии.
  - `food_type`: `"berries"` (срок годности базовый 3600 сек) или `"meat"` (срок годности базовый 4500 сек).
  - `amount`: количество единиц пищи.
  - `created_sim_time`: игровое время создания.
  - `max_freshness_sec`: базовый срок свежести.
  - `spoilage_progress`: прогресс порчи от 0.0 до 1.0.
* Перекладывание пищи не омолаживает её: дата создания и накопленный `spoilage_progress` сохраняются в объектах и сейвах.
* Снижение порчи амбаром (`granary_spoilage_factor`): наличие амбара снижает скорость порчи (умножает скорость порчи на коэффициент < 1.0, например 0.4).
* Потребление пищи жителями: реализовано по принципу **FIFO (First In, First Out)** — первыми съедаются самые старые партии, предотвращая лишнюю порчу при своевременном потреблении.
* По истечении срока свежести (`spoilage_progress >= 1.0`) испорченная партия списывается со склада с уведомлением игрока через тост.

## 3. Ревизия пассивных вызовов в `sim_daily_tick` и `calculate_daily_production`

1. В `settlement.gd` обнулены и отключены начисления для:
   - `wood_prod = 0.0`
   - `hunt_prod = 0.0`
   - `for_prod = 0.0`
   - `stone_prod = 0.0`
   - `metal_prod = 0.0`
2. Поступление указанных ресурсов в `economy.resources` осуществляется **исключительно** через метод `deposit_resource(...)`, вызываемый физическим агентом-гражданином при завершении пути доставки на склад (`_get_storage_pos`).
